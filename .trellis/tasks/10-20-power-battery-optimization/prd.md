# 设备能耗与电池管理优化

## Goal

设备开机放置、屏幕自动熄灭后掉电过快，放一晚即耗尽无法开机；首页电量偶尔错误显示 0%。
本任务让设备在无人使用时进入两级省电（浅睡 → 深睡），在低电量时主动保护，并修正电量显示，
使“开机放着不管”不再把电池放空，且顶栏电量可信。

## Background（排查结论，基于代码，待实机测电流确认）

### 待机耗电来源

BSP 已实现深睡终端接口（`bsp_battery_sleep` / `bsp_audio_prepare_deep_sleep` / `bsp_i2c_prepare_deep_sleep` /
`bsp_display_prepare_deep_sleep`），但 `firmware/main/` 从未调用；空闲时只关背光（`rb_app.c:60-80`，120 s）。

| # | 耗电项 | 证据 |
|---|---|---|
| A1 | CPU 160 MHz 常转，无自动 light sleep | `sdkconfig.defaults` 未开 `CONFIG_PM_ENABLE` / `CONFIG_FREERTOS_USE_TICKLESS_IDLE`；`CONFIG_FREERTOS_HZ=1000` |
| A2 | Wi-Fi 常连，熄屏后仍每 15 s TCP 探测服务器 | `rb_net.c:37` `PROBE_INTERVAL_MS`；`rb_net.c:622-628`；`rb_net.c:228` `WIFI_PS_MIN_MODEM` |
| A3 | 熄屏不让 LCD 控制器 Sleep In | `main.c:run_actions` 仅 `bsp_display_backlight()` |
| A4 | LVGL 刷新任务 20 ms 周期常驻 | `CONFIG_LV_DEF_REFR_PERIOD=20` |
| A5 | 按键组件 esp_timer 5 ms 轮询 ADC；网络任务 200 ms、app 任务 250 ms 周期唤醒 | `bsp_button.c:button_level`；`rb_net.c:631`；`main.c` `TICK_MS` |
| — | ES8311 已正确处理（开机即 sleep，录音后 sleep） | `rb_audio.c:90,106` |

粗估熄屏待机电流为数十 mA，520 mAh 电芯十几小时耗尽，与现象吻合。

### 电量显示 0% 的原因

| # | 问题 | 证据 |
|---|---|---|
| B1 | 初始化等待 SOC 就绪时接受首次读到的 0 | `bsp_battery.c:cw_wait_soc_ready` 判定仅 `soc <= 100` |
| B2 | 待机页不定时重绘，电量读数可长期停在旧值 | `main.c:refresh_info` 只在 `dirty` 时读；`rb_app.c:handle_tick` 的 IDLE 视图不产生 `RB_ACT_RENDER` |
| B3 | 电池耗尽后 CW2017 掉电，下次开机必走“写 profile + 重启”路径，正好触发 B1 | `bsp_battery.c:bsp_battery_init` profile 不匹配分支 |
| B4 | UI 直接显示原始 SOC，无合理性校验 | `rb_ui.c:484-495` |

## Decisions

- D1：掉电场景是**开机放置、熄屏后**持续掉电，问题在固件；关机态硬件漏电不在本任务范围。
- D2：采用**两级省电**：熄屏即进入浅睡（保持 Wi-Fi，按键可直接录音），熄屏后再无操作 15 分钟进入深睡（任意功能键唤醒并重启）。
- D3：参数与规则按下表执行（用户确认 2026-10-20）。
- D4（用户新增 2026-10-20）：主屏幕（待机页）单击「下」键一键进入浅睡。

## Requirements

| ID | 要求 |
|---|---|
| R1 | 调暗 30 s、熄屏 120 s 维持现状；熄屏同时进入浅睡：LCD 控制器 Sleep In、LVGL 暂停刷新、CPU 自动 light sleep、Wi-Fi 保持连接但降低唤醒频率、暂停服务器探测（或拉长到 ≥5 min） |
| R2 | 浅睡中按任意功能键：点亮屏幕并恢复正常运行；首次按键只亮屏（沿用现有规则），待机页按住“上”仍可直接开始笔记录音 |
| R3 | 熄屏后持续无操作 15 min 进入深睡；按任意功能键唤醒，设备重启回到待机页 |
| R4 | 正在连接、录音、确认结束、保存时，不进入任何一级睡眠，也不熄屏（沿用现有背光规则） |
| R5 | 配网 / 配对页 10 min 无操作直接进入深睡 |
| R6 | 进入深睡前按 BSP 文档顺序关闭外设：Wi-Fi 停止 → CW2017 sleep → ES8311 sleep → 释放 I2S/I2C 引脚 → LCD Sleep In 并 hold；按键脚释放 ADC 并切数字输入上拉作为 GPIO 唤醒源；入睡时若有按键按住则推迟 |
| R7 | 低电量：SOC ≤5% 顶栏标红并弹一次提示；SOC ≤2% 或电压低于阈值（暂定 3.3 V，实测后定）时，若在录音先结束并保存，然后显示“电量过低”并进入深睡 |
| R8 | 电量读数修正：初始化须连续读到稳定的非 0 值（或电压证明确为低电）才算就绪；待机期间每 60 s 刷新一次电量；电压正常（> 3.6 V）而 SOC=0 视为无效，不显示该值 |
| R9 | 低电深睡唤醒后若电量仍低于阈值，提示后立即再次深睡，不启动 Wi-Fi |
| R10 | 待机页（`RB_VIEW_IDLE`，屏幕亮或调暗时）单击「下」：立即熄屏并进入浅睡，与 120 s 自动熄屏效果相同，并从此刻开始计算 15 min 深睡倒计时；唤醒规则同 R2。仅主屏幕生效，其他页面「下」键行为不变。待机页提示行改为「下 休眠 · 长按 确定 设置」 |

## Acceptance Criteria

- [ ] AC1（R1）：熄屏后串口/日志显示进入浅睡；实测熄屏待机平均电流较改动前显著下降（目标 ≤ 5 mA，以实测为准并记录数值）。
- [ ] AC2（R2）：浅睡中按“确定”→ 屏幕亮起不开始录音；再按“确定”→ 正常开始会议录音；按住“上”→ 开始笔记录音。
- [ ] AC3（R3）：熄屏 15 min 后进入深睡（日志可见）；按任一功能键唤醒，开机日志显示 GPIO 唤醒原因，回到待机页并重连 Wi-Fi。
- [ ] AC4（R6）：深睡电流实测记录（目标 < 0.5 mA，受硬件静态电流限制）；入睡前按住按键不会出现“睡下即醒”循环。
- [ ] AC5（R4）：会议录音持续 > 20 min 不熄屏、不睡眠、不中断。
- [ ] AC6（R5）：停留在配网页 10 min 无操作后进入深睡。
- [ ] AC7（R7/R9）：用可调电源或低电电池模拟：≤5% 标红提示；低于阈值时录音被保存后深睡；唤醒后电量仍低则立即再睡。
- [ ] AC8（R8）：开机（含 CW2017 重写 profile 场景）不再显示 0%；待机 60 s 内电量数字会刷新；`test_rb_app.c` 等主机单测与 `idf.py build` 通过。
- [ ] AC10（R10）：待机页按「下」→ 屏幕立即熄灭并进入浅睡（日志/电流可见），松键不会被立刻唤醒；再按任一键亮屏回到待机页且不触发录音；之后 15 min 无操作进入深睡；录音页、设置页的「下」键行为不变（`test_rb_app.c` 覆盖）。
- [ ] AC9：开机放置一夜（≥ 8 h）后仍能正常开机使用，记录前后电量。

## Out of Scope

- 硬件改版（功放使能、上拉电阻、电源 IC 静态电流）与关机态漏电。
- 服务端改动。
- 电池 profile 重新标定 / SOC 精度校准。
- 用户可配置的睡眠时长（本期写死为常量）。
