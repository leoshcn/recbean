# 录音笔记与会议录音双模式

## Goal

录音豆有两个使用场景，设备端与网页端都要区分开：

1. **录音笔记**（自己用）：像对讲机——在待机页按住「上」键就收音并实时转写，松开即结束。同一天的所有笔记在网页端汇总成一篇「当日笔记」。
2. **会议录音**（线下会议）：保持现有操作和区分说话人的转写，网页端单独一个入口。

另外增加**热词**：在网页端配置一份热词表，笔记和会议共用，提高专有名词的识别准确率。

## Background / Confirmed Facts

- 现有唯一流程即会议流程：待机单击「确定」开始 → 录音中单击「确定」→ 确认页再按「确定」结束（`firmware/main/rb_app.c` `handle_key`）。录音中「上/下」用于翻看转写。
- BSP 按键只上报 PRESS / CLICK / DOUBLE / LONG，**没有松开事件**（`firmware/components/bsp/src/bsp_button.c` `register_callbacks`）；`main.c:on_key` 目前只用 CLICK 和「确定」LONG，待机页「上」键未被使用。
- 会话任务现在是**收到服务端 started 之后才开始采音**（`rb_session.c` `rb_audio_start` 在 started 之后），连接加 start 通常要零点几秒到两秒；离线环形缓冲约 8 s（`RB_RING_FRAMES`=40）。
- 服务端 `recording` 表没有类型字段（`server/app/store.py` SCHEMA）；ASR 请求固定开启说话人区分（`doubao_asr.py:build_request_params` `enable_speaker_info: True`）。
- 设备字库是完整 GB2312，新增中文提示不用重新生成字库。
- 网页端只有一个录音列表 `/` 和详情页 `/r/:id`（`server/web/src/main.js`）。
- 服务端用的是豆包双向流式优化版 `bigmodel_async`（`.trellis/spec/backend/doubao-asr-and-deploy.md`）。热词通过 `request.corpus.context` 直接发送，内容是 `{"hotwords":[{"word":".."}]}` 序列化成的字符串。按文档，**双向流式只支持约 100 tokens**（`archive/2026-10/10-18-recbean-mvp/research/doubao-streaming-asr-raw.md:220`），超出时是报错还是截断，文档没写。
- 用户已选定：只用直接发热词这一种方式，不接火山自学习平台的热词表。`nostream` 接口没有实时结果，排除。

## Requirements

### R1 设备：录音笔记（按住说话）
- R1.1 待机页按下「上」键立即开始收音（不需要先等服务器连上）；按住期间屏幕显示「正在听」、计时和实时转写；松开即结束并上传保存。
- R1.2 熄屏时按住「上」键同样直接开始收音并点亮屏幕（按住是明确的意图，误触由 R1.3 兜底）。会议的「熄屏时第一次按键只负责点亮」规则不变。
- R1.3 按住不到 0.6 s 就松开：视为误触，丢弃，不在服务端生成记录，提示「按住说话」。
- R1.4 松开后显示保存结果：成功时显示「已记入今日笔记」和本段识别出的文字，约 3 s 后自动回待机（任意键可提前返回）；失败时显示原因（服务器离线 / 未保存等，沿用现有提示）。
- R1.5 Wi-Fi 未连接时按住「上」：提示 Wi-Fi 离线，不开始。
- R1.6 笔记录音中其他按键一律忽略。
- R1.7 按下后服务器连接中、断网续传期间的音频先进本地缓冲，连上后补发，开头不丢字；缓冲溢出（约 8 s 连不上）时按现有规则结束并提示。

### R2 设备：会议录音
- R2.1 操作保持不变（单击「确定」开始，「确定」+确认结束，上下翻看）。
- R2.2 待机页提示文案同时说明两种操作，例如「按 确定 会议录音」「按住 上 记笔记」「长按 确定 设置」。

### R3 服务端
- R3.1 每条录音带类型 `kind`：`note` 或 `meeting`。设备 start 消息带上模式；老固件不带时按 `meeting` 处理；已有录音迁移为 `meeting`。
- R3.2 笔记模式关闭说话人区分，所有句子归到同一说话人。
- R3.3 默认标题区分：「会议 MM-DD HH:MM」/「笔记 MM-DD HH:MM」。
- R3.4 按天（服务端时区，环境变量 `TZ_NAME`，默认 `Asia/Shanghai`）聚合笔记：提供日列表、某天全部笔记段、某天导出 TXT 的接口。
- R3.5 现有录音接口支持按 `kind` 过滤。

### R4 网页端
- R4.1 顶部导航：**笔记** / **会议** / 设备配对；首页默认进入「笔记」。
- R4.2 笔记首页：按日期倒序列出每天的笔记（日期、段数、总时长、首句预览）。
- R4.3 当日笔记页：把当天所有笔记段按时间顺序排成一篇，每段显示时间（HH:MM）和文字，不显示说话人；每段可播放本段音频、编辑文字、删除；整页可「复制全文」和「导出 TXT」；有正在录的段时自动刷新。
- R4.4 会议页：即现有录音列表（只列 `meeting`），详情页保持现有功能（说话人改名/合并、逐句编辑、导出）。

### R5 热词（笔记与会议共享）
- R5.1 网页导航新增「热词」页：添加（支持一次粘贴多行，一行一个词）、修改、删除、上移/下移排序。词去掉首尾空白后为 1–32 个字，不允许重复。
- R5.2 页面显示额度：已占用 / 总额度（估算的 token 数）。按列表顺序从上往下累加，超出额度的词标为「未生效」，不发给识别服务。
- R5.3 每次开始录音（笔记或会议）时，服务端读取当前生效的热词，随识别请求一起发送。改动只影响之后开始的录音，正在录的不受影响。
- R5.4 没有热词时不发 `corpus` 字段，行为与现在相同。
- R5.5 额度默认 100，可用环境变量 `HOTWORD_TOKEN_BUDGET` 调整。token 估算规则和实际上限在实现时用真实接口实测后确定，并写进 spec。

## Acceptance Criteria

- [ ] AC1（R1.1/R1.7）待机页按住「上」讲一句话再松开：屏幕在按下时立刻进入「正在听」，按下后立即开口说的第一个字也出现在转写里；网页「笔记」当天页面出现这一段。
- [ ] AC2（R1.3）快速点一下「上」：设备提示「按住说话」，服务端不产生新记录。
- [ ] AC3（R1.2）熄屏状态下按住「上」说话：屏幕点亮且这段被记录。
- [ ] AC4（R1.4）松开后设备显示「已记入今日笔记」和本段文字，约 3 s 回待机。
- [ ] AC5（R2）单击「确定」开始会议录音，操作和结果与改动前一致，网页出现在「会议」列表，区分说话人。
- [ ] AC6（R3.1）老数据迁移后都出现在「会议」列表；不带 mode 的 start 生成 `meeting`。
- [ ] AC7（R3.2）笔记段所有句子同一说话人，网页笔记页不显示说话人。
- [ ] AC8（R4.2/R4.3）同一天两段以上笔记合成一页，按时间排列；复制全文/导出 TXT 内容为「HH:MM 文字」逐段排列；单段播放、编辑、删除生效。
- [ ] AC10（R5.1/R5.2）网页热词页能增删改、排序、批量粘贴；重复词和空词被拒绝；额度计数随增删即时变化，超额的词显示「未生效」。
- [ ] AC11（R5.3/R5.4）配置热词后新开始的笔记和会议录音，识别请求里都带上生效的热词（单元测试断言请求参数）；没有热词时请求里不带 `corpus`。
- [ ] AC12（R5.5）真实接口实测：找一个默认识别不对的专有名词，配置热词前后各识别一次，配置后能识别对；热词塞满额度时识别不报错。
- [ ] AC9 服务端 pytest、固件主机测试与 `tools/validate.sh`/构建通过；真机按 AC1–AC5 验收（烧录需用户对具体镜像确认）。

## Out of Scope

- 笔记与会议之间互相转换、把笔记段挪到别的日期。
- 笔记的总结、待办提取等 AI 后处理。
- 笔记模式下的设备端翻看历史笔记。
- 公网访问、登录鉴权（维持现状仅局域网）。
- 火山自学习平台热词表（`boosting_table_id`）、按模式分别配置热词、记录每条录音当时用了哪些热词。
