# 录音豆：按键录音、实时分说话人转写、Web 查看编辑

## Goal

把 FoloToy AI Passport 做成"录音豆"：按设备按键开始/结束录音，录音过程中屏幕实时显示区分说话人的转写文本；录完后在局域网 Web 页面查看、回放并修改该次录音内容。语音识别使用豆包大模型流式语音识别。

## Background / Confirmed Facts

- 硬件：ESP32-C3、8 MB Flash、无 PSRAM；ST7789 240×320 竖屏；ES8311 录音；3 个功能键（上/下/确定，单 ADC）+ 电源键。详见 `research/findings.md`。
- 固件基线：`D:/project/ai-passport` 的 `main@0b9e4c8`；`feature/xhs-dashboard` 提供配网、Docker 后端、设备配对的可复用模式。
- 豆包流式 ASR（`bigmodel_async`）支持流式说话人分离：`enable_speaker_info` + `ssd_version="200"` + `enable_nonstream`，仅中英文默认模型，16 kHz s16le PCM；说话人标签随定稿句返回（`research/doubao-streaming-asr-raw.md`）。
- 部署：测试机 192.168.2.144，`/root/recbean`，Docker Compose；登录凭据由用户在对话中提供，不写入仓库。
- 本仓库 `.trellis/spec/` 仍是模板，代码落地后再补规范（不阻塞本任务）。

## Key Decisions

- D1 架构：服务器中转。设备 → ws（16 kHz PCM）→ recbean 服务 → 豆包；服务回推带说话人转写，持久化音频与转写。豆包密钥只在服务端。
- D2 第一版只在测试机局域网跑通：设备↔服务明文 ws + 设备令牌鉴权；服务器地址设备端可配置；Web 不做登录。公网部署（wss/TLS、Web 登录、域名证书）为下一阶段，协议需可平滑升级。
- D3 Web 范围：列表（倒序、时长、说话人数、首句、删除）；详情按句显示说话人+时间+文本；编辑句子文本、说话人改名（整份同步）、句子改归说话人、改标题；音频回放且点句跳转；导出 TXT。
- D4 设备交互：待机页（单击确定开始、长按确定进设置、Wi-Fi/服务器状态、右上电量）；录音页（红点+计时、定稿句带"说话人N"并着色、进行中句灰色、自动滚动、上/下翻看数秒后回到最新、单击确定→"再按确定结束"二次确认）；结束页（已保存、时长、句数、Web 地址，数秒后或任意键回待机）；设置页（重新配网、服务器地址、设备信息）。配网热点 `RecBean-Setup` 填 Wi-Fi 与服务器地址，4 位配对码在 Web 确认。内嵌 GB2312 16 px 字库。
- D5 仓库：全部在 recbean 仓库——`firmware/`（导入上游基线并重写应用）、`server/`（后端+前端）、根目录 `docker-compose.yml`；`firmware/UPSTREAM.md` 记录上游来源。
- D6 音频编码：设备端始终以 IMA-ADPCM（4:1，16 kHz 单声道，约 8 KB/s）上传；断网缓存约 80 KB ≈ 10 s；服务端解码为 PCM 后送豆包并存 WAV。上线前需用同一段录音对比 PCM 与 ADPCM 识别结果，确认无明显劣化。
- D7（2026-10-18，真机测试后追加）Web 增加"合并说话人"：详情页可把说话人 X 的全部句子一次性并入说话人 Y，X 从该录音的说话人列表移除。起因：真机双人对话（大人+孩子）被流式 SSD 拆成 4 人，被拆出的多为 < 1 s 短句；流式 ASR 无阈值/人数参数可调。录后整段重聚类（方案 B）经用户决定**暂缓**（2026-10-18）。实测依据：当前 API Key 仅开通 2.0 资源，`auc_turbo`/`bigasr.auc`（1.0）未开通；极速版 + `volc.seedasr.auc` 可调用但说话人全为 1；标准版 submit/query + `volc.seedasr.auc` 支持 base64 内联音频（文档写 url 必填，实测 data 可用），同一段亲子录音整段重聚类为 3 人（流式为 4 人），孩子仍被拆成 2 人且末段把孩子的"不要"并入大人句——收益有限且每段录音多计一次识别费用。以后可用更多真实录音（成人对话、会议）再评估。
- 技术默认（我方决定）：服务端 Python FastAPI + SQLite + Vue 3，容器内单端口 8080，测试机对外映射 8090（宿主 8080 已被其他服务 expense-gauge 占用）；豆包资源默认 `volc.seedasr.sauc.duration`（2.0 小时版）；单次录音不设硬上限（以电量/网络为界），录音不自动清理。

## Requirements

- R1 按键录音：待机页单击确定开始；录音中单击确定 + 二次确认结束。
- R2 实时转写：录音中屏幕显示定稿句（带说话人编号与颜色）及进行中句子，自动滚动，可上下翻看。
- R3 服务端中转：接收设备音频，调用豆包流式 ASR（说话人分离开启），实时回推结果，保存 WAV 音频与句子。
- R4 Web 查看与编辑：按 D3 范围实现。
- R5 配网与配对：热点配网（Wi-Fi + 服务器地址），配对码确认后设备获得令牌；设置页可重新配网。
- R6 异常降级：开始时服务器不可达→不进入录音并提示；录音中断网→缓存约 10 s 音频（ADPCM）并自动重连，超过缓存时长则结束本次录音、已上传部分保存为 interrupted；ASR 出错→音频照常保存、设备提示、Web 显示异常状态。
- R7 部署：`docker compose up -d --build` 部署于测试机 `/root/recbean`，数据卷持久化，凭据只在测试机 `.env`。
- R8 固件 UI 为全新设计，不沿用 ai-passport 演示菜单/ui_pixel 外壳；电量显示于右上角。

## Acceptance Criteria

- [ ] AC1（R1,R2,R3）真机两人对话 ≥ 2 分钟：开始后 ≤ 3 s 屏幕出现文字；定稿句显示"说话人1/2"且颜色不同；结束需二次确认。
- [ ] AC2（R3,R4）结束后 Web 列表出现该录音，时长、说话人数正确；详情可播放音频，点句子跳到对应时间。
- [ ] AC3（R4）修改句子文本、说话人改名、句子改归说话人、改标题后刷新页面仍保留；导出 TXT 内容与页面一致；删除后列表和音频文件均移除。
- [ ] AC4（R5）新设备首次开机可经 `RecBean-Setup` 完成配网并在 Web 确认配对码；未配对设备连接被拒绝。
- [ ] AC5（R6）服务器停止时按开始→屏幕提示"服务器未连接"不进入录音；录音中断网且在缓存时长内恢复→录音连续无缺失；超时→录音结束，Web 中为 interrupted 且已传内容可见。
- [ ] AC6（R6）豆包凭据错误时录音音频仍保存，Web 标记 asr_error。
- [ ] AC7（R7）测试机 `docker compose ps` 显示服务运行；重启容器后数据仍在；仓库中无真实凭据。
- [ ] AC8（R8）启动与导航路径不出现上游演示 UI；中文转写无缺字方框（常用字范围内）。
- [ ] AC10（D6）同一段两人对话 WAV 分别以 PCM 与 ADPCM 经服务端识别，文本差异很小（字错率差 ≤ 2 个百分点），说话人划分一致。
- [ ] AC11（D7）详情页把说话人 3、4 合并到说话人 2 后，原属 3、4 的句子都显示为说话人 2（保留其名称），说话人列表只剩 1、2；刷新后仍保留；导出 TXT 一致；正在录制的录音不允许合并。
- [ ] AC9 服务端 `pytest` 通过；固件 `tools/validate.sh` 通过；`fake_device.py` 在测试机端到端通过。

## Out of Scope

- 公网部署、wss/TLS、Web 登录、多用户账号（下一阶段）。
- 句子合并/拆分、AI 总结/纪要、全文搜索。
- 设备端离线录音存储与事后补传、设备端回放。
- 豆包以外的识别服务；非中英文语种的说话人分离。
